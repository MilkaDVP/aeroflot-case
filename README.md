# Умная диспетчеризация ОТО воздушных судов на перроне

Конкурсное задание ПАО «Аэрофлот». Система автоматически подбирает
ближайшего свободного сотрудника с действующим допуском на данный тип ВС
и данный вид работ, укладывающегося в регламент прибытия 15 минут,
строит маршрут по рулёжной сети аэропорта и уведомляет инженера.

Полное техническое описание проекта — в [PROJECT.md](PROJECT.md).

---

## Быстрый запуск

```bash
docker compose up --build
```

| Адрес | Что это |
|---|---|
| **http://localhost:8080** | Рабочее место диспетчера |
| **http://localhost:8081** | Приложение инженера (PWA) |
| http://localhost:8000/docs | Автодокументация API (Swagger) |

Войти как `dispatcher / dispatcher`, выбрать аэропорт и дневную смену —
откроется карта с вызовами, сотрудниками, бортами и машинами на стоянках.
Переключатель в правом верхнем углу карты включает спутниковую подложку
(нужен интернет; режим «Схема» работает без него).

Встроенных аэропортов два: **Шереметьево (UUEE)** и **Домодедово (UUDD)**.
Диспетчер привязан к обоим, поэтому видит шаг выбора аэропорта; начальник
смены — только к Шереметьево. Данные аэропортов не смешиваются: сотрудники,
борта, машины и вызовы всегда только выбранного.

**Назначение можно отменить.** В карточке назначенного вызова есть кнопка
«Снять исполнителя»: с причиной вызов возвращается к подбору, сотрудник
освобождается, машина возвращается в парк. Снятый не предлагается повторно,
а в карточке остаётся отметка, кого и почему сняли. Инженер получает
сообщение «вызов снят диспетчером».

## Как проверить решение самостоятельно

Всё меняется из интерфейса, без запросов к API и правки данных.

**Добавить вызов.** Кнопка «Зарегистрировать вызов» слева внизу или клик
по стоянке на карте: борт и тип неисправности. Подбор запускается сразу
при выборе вызова в списке.

**Переместить сотрудника.** Кнопка «Переместить сотрудника» в левом верхнем
углу карты → клик по человеку → клик по новому месту. Время в пути
и предложение системы пересчитываются немедленно: например, перенос
инженера к стоянке вызова меняет расчёт с 9.8 минуты (734 метра) на
3.9 минуты (290 метров). Задание разрешает имитировать координаты
нажатием на карту вместо настоящего GPS.

**Изменить квалификацию.** `admin / admin` → «Администрирование» →
«Сотрудники» → «Изменить»: отметка, типы ВС, срок действия, смена, место.
Если снять у Соколова допуск на A320, он исчезает из кандидатов и
появляется в списке «не подходят» с причиной.

Каждое изменение видно в подборе сразу же — он считается заново при
выборе вызова.

## Администрирование: свои аэропорты, люди, машины, борта

Войти как `admin / admin`, на экране выбора аэропорта нажать ссылку
**«Администрирование»**.

**Аэропорт по коду ИКАО.** Вкладка «Аэропорты» → «Добавить по коду ИКАО»
(например `ULLI`, `UUWW`, `KJFK`). Сервер находит аэродром в OpenStreetMap
по самому коду и выгружает настоящий граф рулёжек — это единственный момент,
когда серверу нужен интернет. Техцентров в OSM не бывает, стоянки размечены
не везде (у Пулково их нет вовсе) — система скажет, чего не хватает.

**Разметка на карте.** «Разметить на карте» открывает редактор поверх
спутникового снимка:

- **Стоянка / Техцентр** — клик по карте ставит новую точку и сам присоединяет
  её к ближайшей точке сети; клик по серой точке сети превращает в стоянку
  (или техцентр) её саму;
- **Перекрёсток** — точка рулёжной сети;
- **Соединить** — клики по точкам подряд тянут рулёжку;
- **Удалить** — клик по точке или связи.

Сервер проверяет граф при сохранении: нужны стоянка и техцентр, все точки
должны быть связаны. Длины считает сам; у выгруженных из OSM рулёжек
сохраняются настоящие длины и изгибы. Можно создать и **пустой аэропорт**
«вручную» — нарисовать учебную схему из нескольких точек, на которой
глазами видно каждый маршрут.

**Люди, машины, борта.** Переключатель аэропорта в шапке, затем вкладки:

- «Сотрудники» — ФИО, отметка, типы ВС, срок, место; флажок «сразу на смене»
  и необязательные логин с паролем для входа в приложение инженера;
- «Спецтранспорт» — позывной и стоянка машины;
- «Борта» — бортовой номер, тип ВС из справочника, стоянка.

После этого аэропорт выбирается на экране смены как любой другой.

**Открыть приложение инженера с телефона.** Телефон и компьютер должны быть
в одной сети. Узнайте адрес компьютера (`ipconfig` в Windows) и откройте:

```
http://192.168.X.X:8081/?api=http://192.168.X.X:8000
```

Параметр `?api=` запоминается, дальше достаточно обычного адреса. В Chrome
приложение ставится на домашний экран через меню «Установить приложение».

База создаётся и наполняется тестовыми данными автоматически при первом
запуске: 18 сотрудников с разными квалификациями, 10 бортов на стоянках,
7 машин спецтранспорта, учётные записи всех ролей и открытые вызовы —
по обоим аэропортам.

## Как проверить работу за две минуты

Через Swagger на `/docs` либо curl:

```bash
# 1. Вход. Аэропорт один, поэтому выбирается автоматически.
TOKEN=$(curl -s -X POST localhost:8000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"dispatcher","password":"dispatcher"}' | jq -r .token)

# 2. Выбор смены.
curl -s -X POST localhost:8000/api/session/airport \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"airport_icao":"UUEE","shift":"day"}'

# 3. Борта на стоянках.
curl -s localhost:8000/api/aircraft -H "Authorization: Bearer $TOKEN"

# 4. Вызов на A320 (борт VP-BZQ, стоянка 31): утечка гидрожидкости.
curl -s -X POST localhost:8000/api/calls \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"aircraft_id":1,"defect_code":"hydraulic_leak"}'

# 5. Подбор исполнителя.
curl -s -X POST localhost:8000/api/calls/1/suggest -H "Authorization: Bearer $TOKEN"
```

**Что важно увидеть в ответе на шаге 5.** У стоянки 31 стоят двое: Волков
у самого борта и Орлов в 94 метрах. Оба попадают в список `rejected`:
у Волкова допуск на B777, а не на A320, у Орлова истекла отметка. Система
назначает Соколова, который находится в 1,7 км, но приезжает на
спецтранспорте за 6,2 минуты. Это и есть разница между интуитивным выбором
диспетчера и расчётом.

Все контрольные сценарии задания разобраны в
**[docs/scenarios.md](docs/scenarios.md)** — с решением системы, «интуитивным»
выбором диспетчера рядом и временем расчёта. Отчёт не пишется руками,
а создаётся заново:

```bash
cd server
python scenarios.py --md ../docs/scenarios.md
```

## Запуск без Docker

Нужен Python 3.11 или новее.

```bash
# Сервер
cd server
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# Веб-диспетчер (в отдельном терминале) — сборка не нужна, это чистая статика
cd web-dispatcher
python -m http.server 8080
```

Открыть `http://localhost:8080`. Адрес API клиент выводит из адреса
страницы; если сервер поднят на другой машине, укажите его явно:
`http://localhost:8080/?api=http://192.168.1.10:8000`.

Графы аэропортов уже лежат в `data/airports/` и закоммичены. Заново
выгружать их не нужно; если всё же требуется:

```bash
python data/fetch_airport.py UUEE        # выгрузка из OpenStreetMap
python data/fetch_airport.py ULLI --auto # границы найти в OSM по коду
python data/fetch_airport.py --list      # какие аэропорты описаны
```

## Тесты

```bash
cd server
python -m unittest discover -s tests -t .
```

180 тестов: маршрутизация, проверка допусков, контрольные сценарии подбора
из требований задания, очередь вызовов, снятие исполнителя и переназначение,
общий парк спецтранспорта, разделение данных по аэропортам, конструктор
аэропортов (импорт по ИКАО без обращения в сеть, проверки графа, сквозной
путь от пустой карты до вызова в телефоне инженера), разграничение доступа,
контракт API, миграции и корректность отметок времени.

---
Граф аэропорта построен по данным **OpenStreetMap** (лицензия ODbL),
выгруженным через Overpass API. Квалификационная модель соответствует
**ФАП-147** и **ФАП-285**, коды неисправностей сгруппированы по главам
**ATA-100**.
